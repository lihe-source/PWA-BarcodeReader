# BarcodePro V3_0

完整、免編譯、免 API 金鑰的 GitHub Pages PWA。沿用原專案網址，支援掃描、圖片解碼、條碼產生、歷史紀錄與設定。所有執行檔均放在同一層，不需要 npm、Cloudflare 或伺服器。

## 升級部署（請依序操作）

1. **在舊版設定頁先匯出 JSON 備份**，保存到檔案 App 或電腦。不要清除瀏覽器資料、快取資料庫或移除 PWA 來嘗試升級。
2. 解壓縮 `PWA-BarcodeReader-V3_0.zip`。ZIP 內只有一個同名資料夾，裡面是全部檔案。
3. 開啟 GitHub 的 `lihe-source/PWA-BarcodeReader`，選 Add file → Upload files，把該資料夾**裡面的檔案**上傳到 repository 根目錄（與現有 index.html 同一層）。不要把整個 V3_0 資料夾套在網站外面。
4. 請一次上傳完整版本並提交，尤其不可漏掉本機 `zxing.min.js`、`bwip-js.min.js`、`decoder-worker.js`、圖示、CSS 或 Service Worker。上傳功能若無法直接覆蓋同名檔，使用 GitHub 編輯／Git 同步更新同名檔案；不要刪除整個 repository。
5. 等候 GitHub Pages 部署工作顯示成功，再開啟 `https://lihe-source.github.io/PWA-BarcodeReader/`。右上角及設定頁應顯示 V3_0。
6. 若暫時仍見 V2_0，保持連線，回舊版設定按「檢查更新」，等候下載完成並重新開啟。必要時在電腦用強制重新整理更新頁面，**不要選「清除網站資料」**。V2 的舊快取策略無法由新版提前修正，因此升級前的備份很重要。
7. 同一瀏覽器／同一網站來源中的 V2 歷史與設定會自動移轉到 V3，原 V2 資料不刪除。換裝置或換瀏覽器時，在「設定 → 還原 JSON 備份」匯入剛才的備份。
8. 設定頁出現「核心離線資源完整（V3_0）」後，再測試斷網重新開啟、掃描、圖片辨識及產碼。

原本的 `libs/`、`icons/`、`db.js`、`export.js`、`ui.js`、`update-config.js` 留在 GitHub 不會被 V3 載入，不需要為了升級冒險先刪除；日後確認新版穩定再整理。新版包已不包含這些舊副本。**上傳替換網站檔案不會主動清除瀏覽器歷史資料**。

## 主要變更

- IndexedDB 儲存，不再自動裁切為 500 筆。實際容量仍由瀏覽器與裝置決定；失敗會提示，不能視為無限儲存。
- V2 自動移轉、V1 手動移轉、JSON 合併還原、設定備份與整批格式驗證。相同內容／格式／來源／時間判為同一事件，不會把不同時間的重複掃描合併掉。
- 全部掃描／產碼函式庫隨包部署並預快取；沒有 CDN 執行依賴。
- 新快取只清除本程式前綴及已知 V2 快取，不碰同網域其他 PWA。
- 每次啟動、回到前景與恢復網路時檢查版本；新檔案備齊後，在安全時機暫存草稿與結果再自動更新。正在辨識、還原、編輯對話框或輸入欄位時會延後套用。
- 原生辨識加 ZXing 背景解碼備援；以可見掃描框為辨識範圍，连续兩次結果一致才接受。快速換鏡頭的舊請求不能關閉新鏡頭。
- 掃描成功後停止解碼，15 秒閒置後停止相機；背景停止相機；返回前景保留上次結果。
- 單次／連續掃描、重複碼冷卻、格式／字元數／前綴檢核。連續掃描強制自動保存；保存失敗會停止續掃以免覆蓋結果。
- 原始空白與換行保留。字元數以 JavaScript 字串長度計算（UTF-16 code units），不是 UTF-8 位元組數。
- 圖片取消、裁切、旋轉、分區重試與多結果選擇；無法保證辨識出圖片裡所有條碼。圖片辨識不會自動保存，請按單筆或全部保存。
- 歷史每頁 30 筆、搜尋、日期／來源／分類篩選、多選、批次刪除、約 9 秒內復原、數量與備註。
- CSV 依選取／篩選匯出。危險公式與数字識別碼會加入文字保護前綴，Excel 可能顯示單引號；需要逐字還原請使用 JSON。
- 重新產碼同步帶回原始格式，EAN／UPC 檢查碼驗證／補碼，PNG、圖片分享、回讀驗證與指定範圍列印。
- 手機同頁結果操作，平板／電腦雙欄，支援橫向、底部安全區、可縮放閱讀與減少動態效果。
- 設定頁的資料管理置於最下方，另有診斷、音效測試、持續儲存請求。

## 使用與限制

- 首次相機權限必須由使用者允許，程式不能繞過系統授權。
- 音效需要瀏覽器允許音訊與第一次觸控，並受音量設定影響；震動、補光燈、變焦、持續儲存及螢幕保持開啟都依裝置支援程度啟用。
- 相機影像與上傳圖片只在本機解碼。除了同站程式資源／版本查詢，不會把條碼資料送到外部服務。使用者主動按分享或開啟外部網址除外。
- 沒有登入／雲端同步。Safari、其他瀏覽器及已安裝 PWA 可能處於不同的儲存環境；請在原本使用的環境先匯出備份。
- 產碼草稿保存在本機；更新時暫存頁面、掃描結果、圖片辨識結果及部分表單欄位。**原始圖片預覽不持久保存，重新載入後若需再次裁切，必須重選圖片。**
- 不支援的條碼格式不會默默轉成 QR。一般 Data Matrix／Code 128 不等同 GS1 格式；本版不提供完整 GS1 AI 解析與 FNC1 編輯，正式工業標籤請依既有規範驗證。
- 列印為等比例圖案放入指定毫米範圍，不代表列印機會自動設定標籤紙。請選 100%／實際大小、匹配紙張尺寸，關閉頁首頁尾，並實際試印掃描。
- 已核准的持續儲存也不是備份；清除網站資料或裝置損壞仍會遺失。JSON 可能包含機密條碼、Wi-Fi 密碼，請妥善保管。
- 圖片上限 30 MB／6,400 萬像素；長邊預縮至 2,600 像素。JSON 還原上限 50 MB／100,000 筆。大檔案解析可能短暫耗時。

## 原始碼分工

| 檔案 | 職責 |
| --- | --- |
| index.html / styles.css | 五個工作頁與響應式介面 |
| app.js | 初始化、設定、頁面切換、草稿與還原流程 |
| storage.js | IndexedDB、移轉、JSON／CSV、交易及條碼檢核 |
| scanner.js | 相機生命週期、辨識範圍、連續掃描與回饋 |
| decoder-core.js / decoder.js / decoder-worker.js | 重用 ZXing 解碼器、背景解碼及降級處理 |
| importer.js / generator.js / history.js | 圖片、產碼及歷史管理 |
| updater.js / service-worker.js | 版本查詢、安全更新及隔離快取 |
| version.js / version.json | 執行版本與遠端版本查詢資訊 |
| verify.cjs / release.cjs | 本機邏輯測試與後續發版工具，不由網頁載入 |

## 驗證與後續更新

`node verify.cjs` 可用 Node.js 20+ 執行，不需安裝 npm 套件。內含條碼像素回讀、資料庫交易模擬與 Service Worker 模擬；**不是手機相機、真實瀏覽器 IndexedDB 或視覺測試的替代品**。驗收項目與測試邊界見 `TEST-REPORT.md`。

後續每次修改程式都必須提高版本號。使用 `node release.cjs V3_0_1` 同步產生 version.js 與 version.json 並執行檢查，接著完整部署所有檔案。不要只改 version.json，也不要在同一版本號下反覆替換資源。可自行編輯 version.json 的 notes 更新說明。

外部函式庫資訊與授權見 `THIRD-PARTY.md`。
